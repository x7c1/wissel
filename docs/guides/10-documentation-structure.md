# Documentation Structure

## Overview

This guide explains the role of each directory under `docs/`.

## Directories

### `guides/`

How-to guides for development: building, installing, debugging, testing, and architecture.

### `tasks/`

Task files that drive single-PR work. Each task lives in `tasks/<year>/<MMDD>-<HHMM>-<slug>.md` and is marked completed in the same commit as the code change it describes.

### `learning/`

Learning notes and reference material gathered during development.

### `concepts/`

Living documentation that defines the shared vocabulary for the product. Concept docs describe what domain terms mean in the product context, not how they are implemented. Unlike task files, concept docs are updated over time.
